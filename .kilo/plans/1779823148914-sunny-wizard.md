# Plan: ULTIMATE FORTUNE 1 Test Suite — PHOS E2E + Psychological Testing

## Context

PHOS (Phosphorus Human Operating Surface) is now a fully-wired omniscient frontend with 10 surfaces, 4 biological spoon-states (CRISIS/SANCTUARY/BRIDGE/QUANTUM), PGLite databases, RAG pipeline, WebSocket IoT, and arcade iframe launching. The `phos/` directory has **zero test files** today. This plan creates a comprehensive Vitest + Playwright test suite with heavy focus on psychological/E2E testing per the P31 SOULSAFE/OQE/WCD methodology and the existing `psychological-flow-suite.mjs` schema.

## Existing Infrastructure to Leverage

- Vitest configs across the monorepo (jsdom for frontend, node for libs)
- Playwright config at `04_SOFTWARE/p31ca/playwright.config.ts` (Astro preview on :4321)
- Existing `psychological-flow-suite.mjs` schema (12 personas, 8 cognitive states, 10 flow paths)
- E2E global setup pattern at `02_Client_or_Misc/tests/e2e/global-setup.ts`
- Coverage thresholds: 80% lines minimum, 95/90/95/95 for `@p31/shared`
- WCD-06 OQE pass/fail table pattern for certification

## Key Design Decisions

### 1. Psychological E2E Testing Approach

The existing `psychological-flow-suite.mjs` uses simulation (no real browser). Our E2E suite **actually tests the running app in a real browser** via Playwright. Each persona journey simulates real user interactions at each spoon state:

- **Automated persona simulation**: Playwright scripts that act like each persona (timing, interaction patterns, decision paths)
- **Cognitive load scoring**: Measure DOM complexity, animation count, color contrast, font size at each spoon state
- **AuDHD-specific tests**: Verify that executive dysfunction accommodations work (reduced choices at low spoons, clear paths, no dead ends)
- **Spoon boundary testing**: Verify exact behavior at 0→1, 2→3, 3→4 transitions (the critical morphing points)

### 2. Test Priorities (FORTUNE 1 = Full Operational Readiness Unified Testing Environment)

Priority 1 — Must pass before any commit:
- All surfaces render without crash at all 4 spoon states
- Spoon state transitions are instant and correct
- Guardian panic protocol works end-to-end
- CRISIS mode blocks interaction appropriately

Priority 2 — Must pass before PR:
- Biological theme tokens match spec at every spoon boundary
- Event logging captures every state change
- LOVE economy transactions are atomic
- LocalStorage persistence survives page reload

Priority 3 — Must pass before staging:
- PGLite reads return expected data shapes
- WebSocket lifecycle (connect, message, error, reconnect)
- iframe game launch/close cycle
- RAG pipeline flow (with mocked backend)

Priority 4 — Certification (weekly):
- 70 TRIPER sentinels (mutation testing)
- Full persona journey simulation
- OQE pass/fail table completion
- Comparative AuDHD vs neurotypical experience metrics

### 3. Coverage Targets (per CWP-P31-PROD-006)

| Layer | Tests | Target | Framework |
|-------|-------|--------|-----------|
| Unit (libs) | 80+ | 85% lines | Vitest |
| Unit (surfaces) | 60+ | 80% lines | Vitest |
| Integration | 40+ | Critical paths | Vitest + mocks |
| E2E smoke | 10 | 100% pass | Playwright |
| E2E biological | 20 | 100% pass | Playwright |
| E2E psychological | 50+ | 85% pass | Playwright |
| TRIPER sentinels | 70 | 70/70 | Vitest mutations |
| **Total** | **330+** | **>80%** | — |

### 4. Spoon State Testing Matrix

Every surface is tested at all 4 spoon states:

| State | Spoons | Expected Behavior |
|-------|--------|-------------------|
| CRISIS | 0 | Black screen, zero animation, gray text, no interaction |
| SANCTUARY | 1-2 | Warm gradients, large buttons, 6s breathing, no sharp edges |
| BRIDGE | 3 | Serif font, muted slate, balanced spacing |
| QUANTUM | 4-5 | Monospace, neon emerald, dense data, angular |

Boundary tests at exact transition points: 0→1, 1→2, 2→3, 3→4, and reverse.
